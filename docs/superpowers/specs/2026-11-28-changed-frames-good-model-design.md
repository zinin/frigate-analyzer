# Изменившиеся кадры — сразу в good-model

**Размер:** небольшое изменение. **Одобрено владельцем:** 2026-11-28 (подход и четыре решения ниже).

## Зачем

26 ноября по дороге у дома прошли две машины и трактор, уведомлений не было. Каскад
`default-model → (если что-то нашлось) good-model` пропускает то, чего не видит малая модель:
на проверенном кадре кроссовера `yolo26s` не видит машину вовсе, а `yolo26x` даёт 0.77.
`good-model` на всех кадрах слишком дорога: без домашнего ПК с хорошей видеокартой детекция идёт
на GTX 1650.

Цель: дёшево поднять качество, не увеличив заметно нагрузку и не добавив ложных срабатываний.

## Что меняется

1. После извлечения кадров анализатор смотрит на первый кадр записи (frame 0).
2. Если он цветной (день), каждый следующий кадр сравнивается с ним. Камера в ночном ИК-режиме
   даёт строго монохромную картинку, поэтому ночью сравнения нет.
3. Изменившийся кадр анализируется сразу `good-model`, остальные — прежним каскадом. Первый кадр,
   ночные записи и монохромные камеры обрабатываются как сейчас.
4. Параметры запросов к vision-api (`conf`, `imgsz`) те же, что и сейчас.
5. Любая ошибка сравнения или `good-model` — прежнее поведение (fail-open).

## Решения владельца

- День определяется по самому кадру (цветность), не по часам.
- Режим включён по умолчанию, выключается переменной окружения.
- Только frigate-analyzer; vision-api не меняется.

## Подходы

| Подход | Итог прогона 920 записей |
|---|---|
| `good-model` на всех кадрах | в 2–4 раза больше нагрузки — отклонён |
| Пропуск неизменившихся кадров + вырезки изменившихся участков | теряет настоящие находки (людей), вырезки почти ничего не дают — отклонён |
| Изменившийся кадр → `good-model`, круглосуточно, включая первый | +19 записей, но ночью из-за снега в ИК время кадра в 3 раза больше — отклонён |
| **Изменившийся кадр → `good-model`, только днём, кроме первого** | **+12 записей** (9 с машинами, 2 с людьми), +5–10 % нагрузки, 0 ложных на 600 пустых — **выбран** |

Прогон: записи с детекциями за 31.10–27.11 и их соседи, проезды 26.11, 600 пустых; сравнение
кадров — прототип на Python.

## Сравнение кадров (из прототипа, на нём получены цифры)

- Рабочий размер: ширина 640 px.
- Монохромность: среднее по пикселям `max(R,G,B) − min(R,G,B)`. ИК-кадры камер дают ровно 0,
  цветные дневные (и заснеженные) — от 4.
- Сравнение: серое изображение с размытием 3×3, компенсация общего сдвига яркости (разность
  медиан), порог разности 22, верхние 8 % (часы камеры) не учитываются, открытие 3×3, расширение
  7×7.
- Кадр изменился, если есть связная область не меньше 300 px или изменено больше 8 % кадра.

## Ограничения

- Хост анализатора нагружен по CPU: сравнение должно стоить десятки миллисекунд на кадр.
- Кадры с камер владельца не коммитятся; тесты — на синтетических картинках.
- Сделать видимым в логе, сколько кадров ушло в `good-model` напрямую, — чтобы оценить нагрузку
  после выката.

## Не входит

Ночные проезды и трактор (модели их не видят и в `good-model`), правило по свету фар, вырезки,
зоны на кадре, изменения трекера, исправление гонки параметров в vision-api (делается отдельно).

## Оставлено исполнителю

Размещение кода, имена, форма проброса признака через пайплайн, порог монохромности (около 1.5),
тексты логов и документации.
